# v2.20 Persistent Routing

## What changed
The app now uses hash-based persistent routes so GitHub Pages/PWA hosting can restore the exact screen after reload without server-side rewrite rules.

### Admin routes
- `#/admin/dashboard`
- `#/admin/clients`
- `#/admin/clients/<client-id>`
- `#/admin/websites`
- `#/admin/websites/<client-id>/<project-id>`
- `#/admin/activity`
- `#/admin/prompts`
- `#/admin/tasks`
- `#/admin/time`
- `#/admin/invoices`
- `#/admin/billing`
- `#/admin/trash`

### Employer routes
- `#/employer/overview`
- `#/employer/websites`
- `#/employer/websites/<project-id>/view`
- `#/employer/websites/<project-id>/intake`
- `#/employer/tasks`
- `#/employer/files`
- `#/employer/work`
- `#/employer/invoices`
- `#/employer/account`

## Behavior
- Refresh restores the current route after Supabase session restoration.
- Browser Back/Forward renders the matching screen.
- Deep Website Project routes restore the same project and mode.
- Wrong-role routes are canonicalized to that role's home page.
- The logo Home action now naturally updates the route to Admin Dashboard or Employer Overview.
- Hash routing is intentionally used because it works reliably on GitHub Pages without rewrite configuration.

## Database
No SQL migration is required for v2.20. This release changes frontend navigation and PWA cache versioning only.
