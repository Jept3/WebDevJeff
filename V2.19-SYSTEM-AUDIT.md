# v2.19 System Audit Summary

## What was simplified

The old system accumulated overlapping file and showcase behaviors over multiple iterations. v2.18 established the Website Project Asset Library as the source of truth. v2.19 continues that cleanup by removing the second/deferred showcase upload path from Production Settings.

Uploads now follow one rule:

- Source files → Project Asset Library, categorized and project-scoped.
- Final logo/screenshots → Admin Showcase, uploaded immediately.
- Production Settings → metadata/status only.

## What was added

### Operational history
`website_project_events` records meaningful project changes at the database layer. This gives the Admin and Employer a consistent timeline without relying on browser-local state.

### Project health
Admin project cards now identify incomplete intake, missing logo, missing site link, or unpublished preview. This makes the Website Projects page usable as an operations queue.

### Activity Center
Admin has a global activity page for Website Project changes across Employers.

### Search / filtering
Website Projects can be searched by website/Employer and filtered by production status.

### UI consistency
The final remaining browser prompt used by the rich text link tool was replaced by a native in-app dialog.

## Architectural recommendation retained

Do not reintroduce a second generic Employer website-file uploader outside the project context. Website assets should remain tied to a Website Project. The general Files page should remain an aggregator/library so files do not become orphaned or ambiguous.
